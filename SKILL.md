# Craft

Craft использует общую визуальную идентичность и отдельные правила для каждого формата.

## Сначала выбери формат

1. Один раз прочитай [общую идентичность](references/identity.md).
2. Прочитай [маршрутизацию форматов](references/surfaces.md) и выбери подходящий.
3. Загрузи только справочники выбранного формата:
   - интерфейсы: [визуальная грамматика](references/interfaces/design-language.md), затем при необходимости [паттерны страниц](references/interfaces/patterns.md) или [компоненты](references/interfaces/components.md);
   - слайды: [визуальная грамматика](references/slides/design-language.md) и [создание презентации](references/slides/authoring.md).
4. Для неподдерживаемого носителя прочитай [правила расширения](references/extending.md), прежде чем создавать новый формат или разовую композицию.

Не переноси размеры интерфейсов в слайды, а масштаб слайдов — в интерфейсы. Форматы делят визуальные принципы, но не компоненты.

## Создание проекта

Интерфейсный отчёт или дашборд:

```bash
python3 {{skill_path}}/scripts/scaffold.py <целевая-папка> \
  --surface interface --template report --title "Название"
```

Каталог интерфейсной дизайн-системы:

```bash
python3 {{skill_path}}/scripts/scaffold.py <целевая-папка> \
  --surface interface --template design-system
```

Презентация:

```bash
python3 {{skill_path}}/scripts/scaffold.py <целевая-папка> \
  --surface slides --title "Название доклада"
```

Старые команды для отчётов и `--template design-system` остаются совместимыми: `interface` используется по умолчанию. Скрипт не перезаписывает непустую папку.

## Порядок работы

1. Определи аудиторию, задачу, реальные данные и требуемое действие или вывод.
2. Создай проект выбранного формата.
3. Замени стартовое содержимое. Удали подстановки и не выдумывай факты.
4. Отредактируй текст: убери общие подводки, раздутую значимость, рекламные оценки и выводы без данных. Сохрани термины и оговорки, которые влияют на смысл.
5. Выстрой информационную иерархию. Используй общие токены и примитивы формата, а не структуру шаблона по инерции.
6. Добавляй JavaScript только для необходимого взаимодействия или механики формата.
7. Открой результат через `file://` и проверь его в условиях использования выбранного формата.
8. При изменении самой Craft запусти `python3 {{skill_path}}/scripts/verify.py`.

## Карта исходников

```text
assets/
├── shared/       # канонические токены и шрифты
├── interfaces/   # отчёты, дашборды, инструменты и каталог
└── slides/       # тема 16:9, механика, подсветка кода и каталог

references/
├── identity.md
├── surfaces.md
├── interfaces/
├── slides/
└── extending.md
```

`assets/shared/tokens.css` — единый источник цвета и типографики. Форматы сопоставляют общие токены со своими смысловыми ролями и самостоятельно определяют композицию, размеры и механику.

## Обязательные требования

- Автономная работа без CDN и сборки, если явно не требуется иное.
- Реальные данные, доступная семантика, видимый фокус и поддержка уменьшения движения.
- Интерактивные элементы сохраняют ширину и высоту при наведении, нажатии, загрузке и смене подписи.
- Прямой текст без выдуманной конкретики, рекламного пафоса и следов диалога с чат-ботом.
- Красный — фирменный акцент Craft. Он может украшать композицию, а в управлении и данных также обозначает действие, состояние или сигнал; смысл не передаётся одним цветом.
- Не используй шаблонные композиции и приёмы из списков запретов в справочниках.
- Локальные классы допустимы для конкретной композиции. Не переноси разовые решения в общее ядро.
