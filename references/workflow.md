# Рабочий процесс Craft

## До каркаса

Определи аудиторию, задачу, реальные данные и действие или вывод. Не начинай с выбора компонентов. Сначала реши, что человек должен понять или сделать.

По умолчанию результат работает через `file://` без сети, CDN и сборки. Если задача требует внешний источник или сборщик, зафиксируй это до создания проекта.

## Создание проекта

Интерфейс, документ или рабочая поверхность:

```bash
python3 {{skill_path}}/scripts/scaffold.py <целевая-папка> \
  --surface interface --title "Название"
```

Презентация:

```bash
python3 {{skill_path}}/scripts/scaffold.py <целевая-папка> \
  --surface slides --title "Название доклада"
```

Генератор создаёт пустую поверхность и не выбирает структуру материала. Он не перезаписывает непустую папку.

## Композиция

Выбери ближайший фрагмент в `craft.json`. До вставки посмотри его контракт:

```bash
python3 {{skill_path}}/scripts/compose.py <целевая-папка> \
  --fragment <id> --list-placeholders
```

Передавай текст через `--set`, семантическую разметку через `--html` или `--html-file`. Используй `--dry-run`, если не уверен в подстановках или целевом контейнере. Скрипт экранирует текст, отклоняет неполный контракт и коллизии `id`, подключает локальные зависимости и вставляет фрагмент атомарно.

Сначала используй зарегистрированный фрагмент, затем примитив темы и только после этого локальный CSS. Локальные классы описывают одну композицию и не становятся частью общего ядра.

Не удаляй `data-craft-layout`, `data-slide-layout`, типизированные подстановки и другие машиночитаемые атрибуты каркаса. Формальные ограничения обеспечивает генератор или проверка. Не повторяй их вручную в локальном коде.

## Содержимое и поведение

Используй данные пользователя. Не добавляй правдоподобные показатели, причины, отзывы, источники или состояния системы. Если данных не хватает, покажи отсутствие или запроси их.

Сохраняй доступную семантику, последовательные заголовки, видимый фокус и поддержку `prefers-reduced-motion`. JavaScript нужен только для требуемого взаимодействия или механики формата. Статическая композиция не требует фреймворка.

После сборки перечитай текст. Удали общие подводки, рекламные оценки, раздутую значимость, выводы без данных и следы диалога с чат-ботом. Сохрани термины и оговорки, которые меняют смысл.

## Проверка

Запусти полный валидатор:

```bash
python3 {{skill_path}}/scripts/check_project.py <целевая-папка>
```

Для полной проверки нужен Chromium. Путь можно передать через `CHROMIUM`. Режим `--static-only` помогает исправить ресурсы и разметку, когда браузер недоступен, но не подтверждает готовность материала.

Валидатор проверяет структуру, автономность, контрольные размеры, доступные имена, тему, механику колоды и PDF. Он не оценивает композицию глазами и не доказывает, что последовательность действий работает. После него обязательно проверь результат вручную.

Для интерфейса:

- открой `index.html` через `file://`;
- просмотри 1440×900, 390×844 и ширину 320 px в обеих темах;
- пройди всю клавиатурную последовательность, включая повторные нажатия стрелок;
- проверь наведение, фокус, выбор, недоступность, загрузку и смену подписей;
- распечатай PDF, просмотри каждую страницу и найди пустые хвосты, одинокие блоки и элементы управления, которые не нужны на бумаге.

Для колоды:

- проверь 1280×720 и узкую область размером с запись на телефоне;
- пройди стрелки, сетку, ленту, полный экран и прямые ссылки;
- проверь обе темы, раскрытие фрагментов и уменьшение движения;
- распечатай PDF и сверь число страниц, фоны, код и медиа.

Считай материал готовым только после валидатора и ручного просмотра. Отчёт агента о собственных проверках не заменяет снимки, PDF или повторяемый сценарий.
