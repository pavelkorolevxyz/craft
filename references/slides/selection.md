# Выбор слайда и сценария показа

Прочитай до каталога и HTML. Для каждого слайда запиши в плане мысль, отношение данных, `data-slide-layout`, первый кадр, следующие раскрытия и причину акцента либо "акцента нет".

Число элементов не выбирает шаблон. Два пункта не означают сравнение, три пункта не означают схему. Не придумывай связи, этапы и победителя ради разнообразия колоды.

## Карта раскладок

В таблице указаны значения `data-slide-layout`. Готовые фрагменты перечисляет `compose.py <проект> --list-fragments`, для остальных используй примитивы темы. Не угадывай идентификатор по имени файла: `split.html` зарегистрирован как `comparison`. Контракт выбранного фрагмента смотри через `--fragment <id> --list-placeholders`, не загружай весь `craft.json`.

| Раскладка | Выбирай для | Не подменяй ею |
|---|---|---|
| `title` | Названия самостоятельного материала | Вывод или переход внутри доклада |
| `cover` | Начала публичного доклада с автором | Заставку перед каждым аргументом |
| `context` | Опыта докладчика, связанного с темой | Результат проекта, для него есть `figure` |
| `section` | Перехода к новому вопросу или крупной части | Содержательный тезис |
| `statement` | Одной мысли с доказательством ранее или далее | Несколько самостоятельных мыслей |
| `list` | Двух и более пунктов одного уровня | Обязательный порядок действий или предметные связи |
| `comparison` | Двух состояний или вариантов по общему критерию | Две независимые темы |
| `quote` | Точных слов проверенного источника с авторством | Собственную формулировку |
| `metrics` | Нескольких величин, доказывающих общий вывод без общей оси | Динамику или справочную таблицу |
| `code` | Вывода о конкретном синтаксисе или условии | Архитектуру или видимый результат |
| `figure` | Изображения с короткой аннотацией | Украшение или длинное объяснение |
| `screenshot` | Одного крупного экрана | Два состояния, для них есть `visual-comparison` |
| `table` | Сверки однородных записей по общим полям | Один визуальный вывод, для него есть `chart` |
| `steps` | Действий в обязательном порядке | План доклада или историю с датами |
| `chart` | Числового отношения на честной шкале | Нечисловые пункты. Вид графика выбирай по [данным](charts.md) |
| `timeline` | Событий с датами или периодами, объясняющими результат | Инструкцию. Номера 01, 02, 03 не заменяют время |
| `flow` | Передачи, зависимости, преобразования или ветвления | Перечень свойств, преимуществ и тем |
| `visual-comparison` | Двух изображений по общему вопросу в сопоставимом масштабе | Несвязанные изображения |
| `resource` | Одного проверенного ресурса с адресом и QR-кодом | Несколько ссылок или финальный контакт |
| `end` | Последней мысли и одного необязательного контакта | Новый аргумент |

## Проверка отношения и акцента

Для сравнения закончи фразу "Сравниваю ___ и ___ по ___". Для "Было / Стало" дополнительно назови один объект и произошедшее изменение. Одинаковые критерии и единицы читаются с обеих сторон. Два варианта без перехода между ними назови прямо. Акцентная правая половина готового шаблона не назначает победителя: равноправным вариантам нужны нейтральные колонки или таблица.

Для каждой стрелки назови предметную связь: "Из ___ в ___ передаётся ___", "___ зависит от ___" или другое точное отношение. Если стрелка означает лишь "следующий пункт речи", это список. Не добавляй ветку или возврат, которых нет в данных.

| Материал | Решение |
|---|---|
| Обучение команды и мониторинг | Два направления работы, `list`, не "Было / Стало" |
| Скорость, доступность, стоимость | Критерии, `list`, не `flow` |
| Установить, настроить, запустить | Действия по порядку, `steps` |
| Клиент отправляет запрос серверу | Реальная передача, `flow` |
| Ручная и автоматическая проверка | `comparison` по времени, охвату и ограничениям с одинаковыми критериями |

Все узлы схемы по умолчанию нейтральны. `.flow-node--accent` допустим, только если тезис выделяет этот узел, например "Валидация отклоняет неверный запрос до записи". Центр композиции не является основанием.

Постоянное выделение предмета отличается от фокуса текущего объяснения. `deck.js` не переносит `.flow-node--accent` при раскрытии. Для обхода схемы безопасный вариант состоит из нейтральных узлов и появления связей с новыми узлами. Движущийся акцент требует локального правила по состояниям и просмотра каждого кадра. Так же проверяй `.is-current`, `.is-after` и выделение строк кода. Фон обложки может быть декоративным, выбор одного элемента среди данных уже сообщает смысл.

## Сценарий раскрытия

Решение о раскрытии обязательно, само раскрытие нет. `reveal.default: none` описывает исходный шаблон и не отменяет последовательное объяснение, нужное докладчику.

| Сценарий | Первый кадр | Каждое следующее нажатие |
|---|---|---|
| Совместное чтение или сравнение | Всё содержимое | Раскрытий нет. Обычно так читают таблицу и обзорную схему |
| Пункты разбираются по очереди | Заголовок, иногда с первым пунктом | Один полный пункт. Пункт, показатель, шаг или событие получает `.frag`. Первый пункт без `.frag` стоит вместе с заголовком, если он задаёт начало истории |
| Объясняется путь объекта | Заголовок и начальный узел | Входящая связь и следующий узел вместе. Ветка после источника, возврат после обоих концов |
| Сначала разбирается первое состояние | Первая сторона | Вторая сторона с подписью и данными целиком |
| Доказательство, затем интерпретация | График или изображение с подписями | Вывод или аннотация. Если вывод уже в заголовке, показывай всё сразу |

Один `.frag` является одним нажатием в порядке HTML, не визуального расположения. Объедини зависимые части в одну обёртку: подпись и значение, стрелку и новый узел, цитату и автора. Не вкладывай `.frag` друг в друга и не показывай пояснение до его предмета. Разметка и счёт страниц описаны в [механике](authoring.md).

## Проверка сценария

Пройди колоду по одному нажатию вперёд и назад. Сверь первый и каждый промежуточный кадр с планом. Нажатие добавляет содержательную часть, не оставляет стрелку без конца, подпись без данных или случайный акцент на пройденном пункте. Учти все раскрытия в длительности рассказа.

Валидатор проверяет часть разметки и механику, но не смысл сравнений и стрелок. Общие условия проверки и сдачи находятся в [рабочем процессе](../workflow.md).
