# Сборка и механика колоды

Выбор формы и сценария живёт в [правилах выбора](selection.md), оформление в [визуальной грамматике](design-language.md). Создание проекта, `compose.py` и общий порядок проверки описаны в [рабочем процессе](../workflow.md).

## Источники

`catalog/slides/index.html` показывает 28 исходных слайдов и 20 раскладок, которые раскрываются в 61 экранную и печатную страницу. Связный пример: `catalog/slides/case-study.html`. Не копируй порядок каталога. В `craft.json` поля `catalogExamples` разбирают конкретные примеры, `layoutGuidance` задаёт контракты раскладок. Для выбранного фрагмента контракт выдаёт `compose.py --list-placeholders`; весь реестр читать не нужно.

Один слайд хранится как одна `<section class="slide" data-slide-layout="…">`. Укажи ближайшую по смыслу зарегистрированную раскладку даже для локальной композиции. Номер страницы оставь в `<p class="slide-number"></p>`, его заполнит механика. Первый заголовок колоды имеет `h1`, остальные слайды могут использовать `.slide-title`.

## Раскрытие

`deck.js` создаёт отдельную страницу для каждого `.frag` в порядке HTML. Число страниц исходного слайда равно `1 + количество .frag`. Каждая получает собственный номер, адрес и страницу PDF. Не дублируй HTML слайда вручную.

Разметка для сценария "заголовок, затем пункты":

```html
<ul class="bullets">
  <li class="frag" data-n="01"><div><h3>Первый тезис</h3></div></li>
  <li class="frag" data-n="02"><div><h3>Второй тезис</h3></div></li>
</ul>
```

Разметка для сценария "начальный узел, затем связь и следующий узел":

```html
<div class="flow place-fill">
  <div class="flow-node"><strong>Клиент</strong></div>
  <div class="flow-step frag">
    <b class="flow-arrow" aria-hidden="true"></b>
    <div class="flow-node"><strong>Сервер</strong></div>
  </div>
</div>
```

Части одного кадра объединяет одна обёртка `.frag`. Вложенный `.frag` создаёт лишний шаг. `deck.js` нормализует смешанное раскрытие перечислений, но не полагайся на исправление: валидатор считает такую исходную разметку ошибкой. `data-shown` обозначает уже открытые части, `data-reveal` временно помечает новое раскрытие вперёд. Эти атрибуты вручную не ставят.

## Числа

Оставляй конечное значение в тексте. `data-count` запускает счёт от нуля только при раскрытии вперёд:

```html
<div class="frag"><p class="type-metric" data-count data-count-duration="1200">24%</p></div>
```

Длительность по умолчанию 900 мс. Суффикс, десятичная запятая и пробелы разрядов сохраняются. При прямой ссылке, возврате назад, печати и уменьшении движения сразу видно конечное значение.

Счёт получают величины, не номера шагов, разделов, пунктов и делений шкалы. В таблице и строке с двумя замерами помечай число внутри обёртки, а не ячейку: `<td class="num"><span data-count>1 240</span></td>`. Так резервируется ширина конечного числа без изменения колонок.

## Код

```html
<pre class="code" data-language="javascript" data-highlight-lines="2-3"><code>function example(input) {
    return transform(input);
}</code></pre>
```

Локальные `code-highlight.js` и Highlight.js подсвечивают синтаксис до раскрытия. Не набирай синтаксические `<span>` вручную. Для смены строк фокуса допустимы соседние слайды с тем же кодом и новым `data-highlight-lines`.

## Управление и доступность

Стрелки и пробел переключают страницы. `G` включает сетку, `L` ленту, `F` полный экран, `T` тему, `H` панель управления. Тема сохраняется в браузере.

Механика назначает слайдам роль, доступное имя с номером и `aria-current="page"`. Имя берётся из первого `h1`, `h2`, `h3` или `.slide-title`. У таблицы нужны заголовок слайда и `caption`: механика связывает их через `aria-labelledby`. Первый объясняет вывод, второй называет набор данных.

Обязательный просмотр каждого кадра описан в [проверке сценария](selection.md), браузерные команды и условия готовности в [рабочем процессе](../workflow.md).
