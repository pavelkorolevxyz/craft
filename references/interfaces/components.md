# Компоненты и примитивы

Базовые классы находятся в `assets/interfaces/theme.css`, а готовые составные блоки — в трёх шаблонах интерфейса. Сначала копируй каноническую разметку из ближайшего шаблона, затем адаптируй содержимое. Для конкретной композиции добавляй локальный CSS. Не копируй `specimen.css` целиком: он нужен только каталогу дизайн-системы.

## Каркас

```html
<main class="shell shell--report" data-craft-layout="report">
  <header class="report-head">...</header>
  <section class="scoreboard">...</section>
  <section class="section">...</section>
  <aside class="callout">...</aside>
</main>
```

`.shell` занимает всю ширину и минимум всю высоту области просмотра. Внешний центрированный контейнер не нужен.

## Заголовок инструмента или отчёта

```html
<header class="report-head">
  <div class="report-head__main">
    <p class="eyebrow">Состояние системы</p>
    <h1>Отчёт за неделю</h1>
    <p class="report-head__lede">Главный вывод одной фразой.</p>
  </div>
  <div class="report-head__aside" aria-label="Параметры отчёта">
    <p>Период: 7 дней</p>
    <p>Обновлено: 2026-08-14</p>
  </div>
</header>
```

Правая колонка существует ради параметров, фильтров или действий. Без них удали её и сделай заголовок одноколоночным.

## Метрики

```html
<section class="scoreboard" aria-label="Ключевые показатели" style="--metrics: 3">
  <div class="metric">
    <strong class="metric__value">98,7%</strong>
    <span class="metric__label">Успешных операций</span>
  </div>
</section>
```

Бери 2–4 метрики в поддержку главного вывода и указывай единицу измерения. Для текстового отчёта ограничься 2–3 метриками и добавь `.scoreboard--compact`, чтобы числа не вытесняли основной текст с первого экрана и оставались строкой на мобильном. Значения нейтральные; `.metric--accent` достаётся одной приоритетной метрике.

## Секция

```html
<section class="section">
  <div class="section-head">
    <h2>Что произошло</h2>
    <p>Источник, период или инструкция по чтению.</p>
  </div>
</section>
```

Абзац внутри `.section-head` расположен под заголовком и работает как подзаголовок. Правую колонку добавляй отдельной локальной композицией только для самостоятельных параметров или действий. `.section--tight` подходит таблицам и плотным журналам, `.section--accent` применяется редко и обычно один раз на странице. Самостоятельная секция начинается с `h2`; вложенные блоки используют `h3`.

## Компоновка

```html
<div class="split">
  <div>Главный материал</div>
  <aside>Сигналы или пояснение</aside>
</div>

<div class="stack" style="--stack-gap: 16px">...</div>
```

`.split` создаёт неравные колонки. Для другой структуры добавь локальный класс сетки, сохранив поля `var(--gutter)`.

В длинном текстовом отчёте добавь `.document-band` на полноширинную секцию: класс рассчитывает одинаковые поля вокруг читаемой колонки, но не обрывает фон и разделительную линию. Самостоятельную полосу метрик или другой блок центрируй целиком через `.document-block`. Не применяй эти классы к дашборду или рабочему инструменту.

## Равные панели

Когда несколько одинаковых блоков стоят в одном горизонтальном ряду, их внутренние разделители должны совпадать. Общий примитив делит каждую панель на шапку, содержимое и итог, а `subgrid` берёт максимальную высоту каждой зоны у соседей.

```html
<div class="equal-panels chart-grid">
  <article class="equal-panel">
    <header class="equal-panel__head">...</header>
    <div class="equal-panel__body">...</div>
    <footer class="equal-panel__foot">...</footer>
  </article>
</div>
```

Не задавай высоту всей группе по самому высокому блоку вручную. Примитив выравнивает только соседей одного ряда. Одиночная панель и панели, сложенные вертикально, сохраняют естественную высоту.

## Ряды данных

```html
<span class="series-key" style="--swatch: var(--data-blue)">Сервис B</span>
```

Роли `--data-red`, `--data-neutral`, `--data-blue`, `--data-amber`, `--data-green` описывают ряды графика и легенду. В печати тема подменяет их тёмными значениями.

## Графики

Рабочие образцы находятся в разделе «Графики» каталога `assets/interfaces/specimen.html`: временной ряд проверяет линии и события, столбцы сравнивают категории с порогом, тепловая карта показывает распределение, кольцевая диаграмма показывает части целого. Все образцы работают без библиотеки и используют роли палитры данных.

Для короткого статического ряда сохраняй линии прозрачными внутри и задавай `vector-effect="non-scaling-stroke"`, чтобы толщина не менялась на узком экране. При растяжении SVG с `preserveAspectRatio="none"` выноси подписи осей в HTML: иначе буквы и цифры деформируются вместе с графиком. В столбчатом сравнении начинай шкалу с нуля и выделяй цветом только значение, которое требует решения. В тепловой карте поясняй направление яркости и не заменяй ей точные значения, когда они нужны для решения. Кольцевую диаграмму ограничивай пятью долями и подписывай проценты рядом: сравнивать близкие углы на глаз трудно.

Под графиком напиши текущее значение и словами объясни заметное событие. Если добавляешь курсор или подсказку, график получает фокус, управление стрелками и живую область с текущим значением.

## Полосы данных

```html
<div class="bar-list" aria-label="Распределение нагрузки">
  <div class="bar">
    <div class="bar__head"><span>Основной поток</span><strong>82%</strong></div>
    <div class="bar__track"><div class="bar__fill" style="--value:82%"></div></div>
  </div>
</div>
```

Шкала начинается с нуля, значение дублируется текстом. Элемент, которому CSS задаёт длину полосы, должен быть блочным.

## Статусы

```html
<span class="status status--ok">стабильно</span>
<span class="status status--warn">проверить</span>
<span class="status status--error">блокер</span>
```

Всегда подписывай статус, цветная точка только дополняет текст. Три тона: `--ok` зелёный, `--warn` янтарный, `--error` красный. Ошибка использует тот же красный, что и любая насыщенная метка.

Цвет достаётся состояниям, которые требуют решения. Рабочее и промежуточное состояние остаётся нейтральным: рамка `--muted` для активного, `--line` с приглушённым текстом для отложенного. Так в колонке горит один-два цвета, а не четыре. Не назначай статусу роль ряда данных.

Состояние внутри строки описания показывай той же точкой перед нейтральным текстом, а не цветным текстом:

```html
<li><span class="status status--warn">Ревью</span> <span>1 из 2 одобрений</span></li>
```

Для состояния, которого нет в трёх базовых тонах, задай `--status` локально вместо новой точки. Один примитив держит одинаковый диаметр по всей странице.

Не складывай разные виды состояния в одну колонку под общим заголовком. Состояние проверки и состояние ревью отвечают на разные вопросы. В статусной колонке используй прямоугольные лейблы одинаковой высоты со спокойной тонировкой, цветной рамкой и явным текстом. Лейбл обнимает содержимое, текст выравнивается по центру. Компактную техническую проверку можно показать знакомой пиктограммой с `aria-label` и подсказкой. Заголовок колонки называет тот смысл, который лежит в её ячейках.

Для тихого выделения строки используй полупрозрачный фон, а не серую поверхность:

```html
<li class="surface-tint surface-tint--error">
  <span class="status status--error">ошибка</span>
  <span>Соединение прервано</span>
</li>
```

`.surface-tint` берёт `--accent-tint`, `.surface-tint--error` — `--error-tint`. Оба сохраняют обычный цвет текста. Такой фон помогает найти строку, но не заменяет подпись.

## Выбор строки в списке

```css
.row:hover { background: var(--surface); }
.row:focus-visible { outline: 2px solid var(--accent-mark); outline-offset: -2px; }
.row[aria-selected="true"] .row__title { color: var(--accent); }
```

Наведение берёт плоскость, выбор — маркер и акцентный заголовок, фокус — контур внутрь строки. Маркер выбора удобно сделать колонкой сетки шириной 3 px во всю высоту в цвете `--accent-mark`: он относится к механике списка, а не изображает неполную рамку карточки. Полная рамка вокруг строки спорит с разделителями и превращает выбор в карточку. Красная заливка внутри списка означает ошибку, а не выбор.

Клавиша, которая переводит выбор, меняет только `aria-selected` и не переносит фокус. Иначе выделение и фокус видны одновременно и читаются как два курсора.

## Переключатель режима

```html
<div class="segmented" role="radiogroup" aria-labelledby="mode-label">
  <label><input type="radio" name="mode" value="all" checked><span>Все</span></label>
  <label><input type="radio" name="mode" value="error"><span>Ошибки</span></label>
</div>
```

Выбор одного значения из нескольких — радиогруппа, а не набор кнопок. Поле ввода остаётся в разметке и получает фокус, поэтому стрелки переключают режим сами. Держи 2–5 вариантов с короткими подписями; для длинного списка бери `select`.

## Таблица

```html
<table class="data-table">
  <thead><tr><th>Поток</th><th>Состояние</th><th>Задачи</th></tr></thead>
  <tbody>
    <tr><td>Основной</td><td><span class="status status--ok">норма</span></td><td>64</td></tr>
    <tr class="total"><td>Всего</td><td>1 поток</td><td>64</td></tr>
  </tbody>
</table>
```

Таблица уместна, пока ячейку можно прочитать взглядом по колонке. Если в строке живёт предложение, на узком экране разверни её в запись: скрой шапку, оставь главное поле строкой, а остальные поля подпиши через `data-label`.

```css
@media (max-width: 520px) {
  .actions-table thead { display: none; }
  .actions-table tr { display: block; }
  .actions-table td { display: inline; }
  .actions-table td:first-child { display: block; }
  .actions-table td[data-label]::before { content: attr(data-label) ": "; }
}
```

Подпись и значение остаются одним куском: пара не переносится по строкам. Числовую таблицу так не разбирай — в ней прокрутка сохраняет сравнение по колонке.

Заголовок и содержимое колонки используют одно горизонтальное выравнивание: текст влево, числа вправо. Правило действует и на списки, визуально собранные как таблица. Если назначение таблицы неочевидно, добавь `<caption>` или заголовок секции.

## Кнопки и поля

```html
<button class="button button--primary">Сформировать</button>
<button class="button">Экспортировать</button>
<label for="period">Период</label>
<span class="select-control">
  <select id="period"><option>7 дней</option></select>
  <svg class="select-control__icon" viewBox="0 0 12 8" aria-hidden="true">
    <path d="m1 1 5 5 5-5"/>
  </svg>
</span>
```

Минимальная высота интерактивного элемента — 44 px. У `select` нативную стрелку заменяет `.select-control__icon`: при наведении усиливаются рамка и стрелка, при фокусе стрелка получает акцентный цвет, недоступное состояние остаётся приглушённым. Кнопка не меняет размер при смене состояния. Если подписи различаются по длине, положи обе в одну ячейку через `.button--stable`:

```html
<button class="button button--stable" aria-pressed="false">
  <span class="button__label button__label--rest">Пауза</span>
  <span class="button__label button__label--pressed">Продолжить</span>
</button>
```

Тема скрывает неактивную подпись через `visibility`, но обе участвуют в расчёте размера. То же правило действует на соседний статус: если рядом с кнопкой текст меняется, оба варианта занимают одну ячейку. Проверяй не только ширину кнопки, но и её координаты до и после действия.

## Переключатель темы

Общий файл `assets/interfaces/theme.js` выбирает тему по параметру `?theme=`, сохранённому значению или системной настройке. Подключай его в `head` до таблиц стилей, чтобы страница сразу получила правильный `data-theme`.

```html
<script src="theme.js"></script>
<button class="button button--stable button--icon theme-switch"
  type="button" data-theme-toggle aria-pressed="false">
  <span class="button__label button__label--rest">иконка солнца</span>
  <span class="button__label button__label--pressed">иконка луны</span>
</button>
```

В реальной разметке текст из примера заменяют встроенные SVG-пиктограммы. Скрипт задаёт кнопке `aria-label` и `title`, сохраняет явный выбор и следит за системной темой, пока пользователь не переключил её сам. График, который читает CSS-цвета из `getComputedStyle`, перерисовывай по событию `craft-themechange`.

## Навигация по длинному документу

Подключи `section-nav.js` и отметь контейнер ссылок атрибутом `data-section-nav`. Скрипт выставляет `aria-current` по прокрутке страницы. Если на мобильном ссылки лежат в горизонтальной ленте, активная ссылка автоматически перемещается в видимую часть.

```html
<nav class="section-nav" aria-label="Разделы документа">
  <div class="section-nav__links" data-section-nav>
    <a href="#summary">Сводка</a>
    <a href="#details">Детали</a>
  </div>
</nav>
<script src="section-nav.js" defer></script>
```

Навигация нужна длинному документу, когда `h1` уезжает за пределы экрана. Короткому отчёту она только отнимает место. В печати навигацию скрывай.

## Горячие клавиши

Добавляй горячие клавиши в инструменты, где пользователь многократно повторяет одно действие: идёт по очереди, запускает обновление, переводит фокус в поиск. Одноразовому отчёту они не нужны.

- у каждого действия остаётся видимая кнопка, ссылка, поле или обычная навигация;
- показывай клавишу рядом с управлением или в компактной памятке через `<kbd>`;
- не перехватывай ввод внутри `input`, `textarea`, `select` и `contenteditable`;
- не занимай сочетания браузера и операционной системы;
- одиночные буквы подходят только частым обратимым действиям;
- игнорируй `event.repeat`, если повторный запуск создаёт лишнюю работу;
- у связанного элемента указывай `aria-keyshortcuts`, обработчик всё равно нужен;
- после действия сохраняй или предсказуемо перемещай фокус и сообщай результат видимым состоянием или `aria-live`;
- не открывай модальное окно ради списка клавиш: хватит строки подсказок или `<details>`.

Для физических клавиш навигации используй `event.code`, чтобы раскладка не меняла расположение команд. Для символа, который пользователь вводит, проверяй `event.key`.

```js
addEventListener("keydown", (event) => {
  const target = event.target instanceof Element ? event.target : null;
  const typing = target?.matches("input, textarea, select, [contenteditable]");

  if (event.key === "/" && !typing) {
    event.preventDefault();
    document.querySelector("#queue-search").focus();
    return;
  }

  if (typing || event.repeat) return;
  if (event.code === "KeyJ") selectNext();
  if (event.code === "KeyK") selectPrevious();
});
```

Начни с двух или трёх команд, которые сокращают реальную повторяющуюся работу.

## Текстовый отчёт

```html
<section class="section">
  <article class="prose">
    <h2>Вывод</h2>
    <p>...</p>
    <pre><code>...</code></pre>
  </article>
</section>
```

`.prose` ограничивает длину строки, но не ширину рабочей поверхности.

## Финальное действие

```html
<aside class="callout">
  <strong>Следующий шаг</strong>
  <p>Решение, срок и ответственный.</p>
</aside>
```

Добавляй блок, только если у страницы есть следующее действие. Справочнику и исследовательскому инструменту он не нужен.
