# Компоненты и примитивы

Базовые классы находятся в `assets/interfaces/theme.css`. Для конкретной композиции добавляй локальный CSS. Не копируй `specimen.css` целиком: он нужен только каталогу дизайн-системы.

## Каркас

```html
<main class="shell">
  <header class="report-head">...</header>
  <section class="scoreboard">...</section>
  <section class="section">...</section>
  <aside class="callout">...</aside>
</main>
```

`.shell` занимает всю ширину и минимум всю высоту области просмотра. Не добавляй внешний центрированный контейнер.

## Заголовок инструмента или отчёта

```html
<header class="report-head">
  <div class="report-head__main">
    <p class="eyebrow">Состояние системы</p>
    <h1>Отчёт за неделю</h1>
    <p class="report-head__lede">Главный вывод одной фразой.</p>
  </div>
  <div class="report-head__aside" aria-label="Параметры отчёта">
    <p>Период: 7 дней</p>
    <p>Обновлено: 2026-08-14</p>
    <p>Источник: локальные данные</p>
  </div>
</header>
```

Оставляй правую колонку только для параметров, фильтров или действий. Если их нет, удали колонку и сделай заголовок одноколоночным.

## Метрики

```html
<section class="scoreboard" aria-label="Ключевые показатели" style="--metrics: 3">
  <div class="metric">
    <strong class="metric__value">98,7%</strong>
    <span class="metric__label">Успешных операций</span>
  </div>
</section>
```

Используй 2–4 метрики в поддержку главного вывода. Указывай единицу измерения. По умолчанию значения нейтральные; добавляй `.metric--accent` только приоритетной метрике.

## Секция

```html
<section class="section">
  <div class="section-head">
    <h2>Что произошло</h2>
    <p>Источник, период или инструкция по чтению.</p>
  </div>
  <!-- содержательная композиция -->
</section>
```

`.section--tight` подходит для таблиц и плотных журналов. `.section--accent` применяется редко, обычно один раз на странице. Самостоятельная `.section` начинается с `h2`; локальные блоки внутри неё могут использовать `h3`. Если панель идёт сразу после заголовка страницы и не вложена в секцию, её заголовок тоже остаётся `h2`, даже при кегле локального заголовка.

## Компоновка

```html
<div class="split">
  <div>Главный материал</div>
  <aside>Сигналы или пояснение</aside>
</div>

<div class="stack" style="--stack-gap: 16px">...</div>
```

`.split` создаёт неравные колонки. Для иной структуры добавь локальный класс сетки, сохраняя поля `var(--gutter)` и интервалы 8–32 px.

## Ряды данных

```html
<span class="series-key" style="--swatch: var(--data-blue)">Витрина</span>
```

Роли `--data-red`, `--data-neutral`, `--data-blue`, `--data-amber`, `--data-green` описывают ряды графика и легенду. Обычно красный достаётся приоритетному ряду, остальные назначаются по мере добавления. Если красный уже обозначает ошибку или превышение порога на этом же экране, обычные категории начинают с нейтрального, синего, янтарного и зелёного. В печати тема подменяет эти роли на тёмные значения, поэтому график остаётся читаемым на бумаге.

## Полосы данных

```html
<div class="bar-list" aria-label="Распределение нагрузки">
  <div class="bar">
    <div class="bar__head"><span>Основной поток</span><strong>82%</strong></div>
    <div class="bar__track"><div class="bar__fill" style="--value:82%"></div></div>
  </div>
</div>
```

Шкала начинается с нуля. Продублируй значение текстом: длины полосы недостаточно для передачи данных. Элемент, которому CSS задаёт длину полосы через `width` или `height`, должен быть блочным. Тема уже задаёт `.bar__fill { display: block }`; для локального варианта на `span` добавь то же правило, иначе браузер проигнорирует размер строчного элемента.

## Статусы

```html
<span class="status status--ok">стабильно</span>
<span class="status status--warn">проверить</span>
<span class="status status--error">блокер</span>
```

Всегда подписывай статус. Цветная точка только дополняет текст.

Три статуса различимы по тону: `--ok` зелёный, `--warn` янтарный, `--error` красный. Ошибка использует тот же красный, что и любая другая насыщенная метка, отдельного оттенка для неё нет. Не вводи четвёртый статус и не приглушай точку — в длинном журнале различие определяется за долю секунды именно по ней.

Цвет достаётся состояниям, которые требуют решения. В очереди задач блокер берёт `--error`, готовность к действию — `--ok`, а рабочее и промежуточное состояние остаётся нейтральным: рамка `--muted` для активного и `--line` с приглушённым текстом для отложенного. Так в колонке горят два цвета, а не четыре. Не назначай `--data-blue` или другую роль ряда данных статусу: эти цвета описывают график, а синий текст читается как ссылка.

Состояние внутри строки описания показывай точкой перед нейтральным текстом, а не цветным текстом:

```html
<li><strong class="state-dot" data-state="warn">Review</strong> <span>1 из 2 одобрений</span></li>
<li><span class="state-dot" data-state="changes">Есть замечания</span></li>
```

```css
.state-dot { display: inline-flex; align-items: center; gap: var(--space-2); }
.state-dot::before { content: ""; width: 8px; height: 8px; flex: none; border-radius: 50%; background: var(--dot, var(--muted)); }
.state-dot[data-state="ok"] { --dot: var(--ok); }
```

Одна страница держит один диаметр точки и одну высоту лейбла. Разные размеры кружков и разный кегль подписей рядом сообщают о разной важности, даже если её нет. Если в соседних блоках состояния описаны и точкой, и лейблом, оставляй общий примитив точки и меняй только цвет.

Не складывай разные виды состояния в одну колонку под общим заголовком. Статус ревью и состояние сборки отвечают на разные вопросы, поэтому получают отдельные колонки либо одна из проверок уходит в панель деталей. В отдельной статусной колонке используй прямоугольные цветные лейблы одинаковой высоты: спокойная тонировка, цветная рамка и явный текст. Лейбл обнимает содержимое, а текст выравнивается по центру; не растягивай короткий статус на всю ширину колонки. Цвет не заменяет подпись. Компактную техническую проверку показывай знакомой пиктограммой, например галочкой, часами или крестом, с `aria-label` и подсказкой. Заголовок колонки называет именно тот смысл, который содержат её ячейки.

Для тихого выделения строки или области используй полупрозрачный фон, а не серую поверхность:

```html
<li class="surface-tint surface-tint--error">
  <span class="status status--error">ошибка</span>
  <span>Соединение прервано</span>
</li>
```

`.surface-tint` берёт `--accent-tint`, а `.surface-tint--error` — `--error-tint`. Оба сохраняют обычный цвет текста и линии. Такой фон только помогает найти строку; подпись статуса остаётся обязательной.

Не используй красный фон для выбранной строки списка. Красная заливка внутри списка сообщает об ошибке или блокере. Выбранную строку обозначай отдельной колонкой-маркером шириной 3 px во всю высоту в цвете `--accent-mark`, акцентным заголовком `--accent` и `aria-selected="true"`. Маркер входит в сетку списка, а не имитирует неполную рамку карточки. Не обводи всю строку: полная рамка спорит с разделителями списка и превращает выбор в отдельную карточку.

Наведение, выбор и фокус различаются средством, а не силой одного и того же приёма:

```css
.row:hover { background: var(--surface); }
.row:focus-visible { outline: 2px solid var(--accent-mark); outline-offset: -2px; }
.row[aria-selected="true"] .row__title { color: var(--accent); }
```

Наведение берёт плоскость `--surface`, выбор — маркер и акцентный заголовок, фокус — контур внутрь строки. Не отдавай выбору ту же плоскость, что и наведению: тогда наведённая строка выглядит выбранной. Не гаси контур фокуса ради фона — фон уже занят наведением, а без контура строка теряет видимый фокус. Контур рисуется внутрь через отрицательный `outline-offset`, поэтому не сдвигает раскладку и не спорит с разделителями.

Клавиша, которая переводит выбор, меняет только `aria-selected` и не переносит фокус на строку: иначе выделение и фокус видны одновременно и читаются как два разных курсора. Фокус остаётся там, где его оставил пользователь.

## Переключатель режима

```html
<div class="segmented" role="radiogroup" aria-labelledby="mode-label">
  <label><input type="radio" name="mode" value="all" checked><span>Все</span></label>
  <label><input type="radio" name="mode" value="warn"><span>Предупреждения</span></label>
  <label><input type="radio" name="mode" value="error"><span>Ошибки</span></label>
</div>
```

Выбор одного значения из нескольких — это радиогруппа, а не набор кнопок. Кнопка запускает действие, переключатель показывает текущий режим и не сбрасывает соседей вручную. Держи 2–5 вариантов с короткими подписями; для длинного списка бери `select`.

Поле ввода остаётся в разметке и получает фокус с клавиатуры, поэтому стрелки переключают режим сами. Не заменяй радиокнопку на `<button aria-pressed>`.

## Таблица

```html
<table class="data-table">
  <thead><tr><th>Поток</th><th>Состояние</th><th>Задачи</th></tr></thead>
  <tbody>
    <tr><td>Основной</td><td><span class="status status--ok">норма</span></td><td>64</td></tr>
    <tr class="total"><td>Всего</td><td>1 поток</td><td>64</td></tr>
  </tbody>
</table>
```

Если назначение таблицы неочевидно, добавь `<caption>` или заголовок секции. Не выделяй итоговую строку красным без содержательного приоритета.

Заголовок и содержимое каждой колонки используют одно горизонтальное выравнивание. Текст обычно выравнивается влево, числа вправо. Не ставь заголовок по центру или справа над ячейками, которые начинаются слева. Это правило действует и на списки, визуально собранные как таблица.

## Кнопки и поля

```html
<button class="button button--primary">Сформировать</button>
<button class="button">Экспортировать</button>
<label for="period">Период</label>
<select id="period"><option>7 дней</option></select>
```

Базовый `theme.css` содержит кнопки. Стили полей, фильтров и сложных элементов управления добавляй локально под задачу, опираясь на каталог. Минимальная высота интерактивного элемента — 44 px.

Кнопка не меняет размер при смене состояния. Если подписи различаются по длине, положи обе в одну ячейку через `.button--stable`:

```html
<button class="button button--stable" aria-pressed="false">
  <span class="button__label button__label--rest">Пауза</span>
  <span class="button__label button__label--pressed">Продолжить</span>
</button>
```

Тема скрывает неактивную подпись через `visibility`, но обе подписи участвуют в расчёте размера. При переключении меняй только `aria-pressed`. Не компенсируй скачок случайным `min-width`, если можно зарезервировать размер по реальному содержимому. Наведение, фокус, нажатие и загрузка также не меняют внутренние поля, толщину рамки или кегль.

То же правило действует на соседний статус. Если рядом с кнопкой текст меняется с «обновлено» на «пауза», оба варианта занимают одну ячейку, а не пересобирают строку управления. Проверяй не только ширину кнопки, но и её координаты до и после действия.

Кнопка, которая меняет выбранную строку, страницу или содержимое панели, остаётся вне перерисовываемого контейнера. После действия она сохраняет координаты и остаётся под курсором. Закрепи такие кнопки в заголовке панели или постоянной панели управления; не создавай их заново вместе с содержимым.

## Горячие клавиши

Добавляй горячие клавиши в рабочие инструменты, где пользователь многократно выполняет одно и то же действие: перемещается по очереди, запускает обновление, ставит поток на паузу или переводит фокус в поиск. Для одноразового отчёта они обычно не нужны.

Правила:

- у каждого действия остаётся видимая кнопка, ссылка, поле или стандартный способ навигации;
- показывай клавишу рядом с управлением или в компактной памятке через `<kbd>`;
- не перехватывай ввод внутри `input`, `textarea`, `select` и элементов с `contenteditable`;
- не занимай сочетания браузера и операционной системы;
- одиночные буквы подходят только для частых обратимых действий;
- опасные и необратимые действия не запускаются одиночной клавишей;
- игнорируй `event.repeat`, если повторный запуск может навредить или создать лишнюю работу;
- у связанного элемента указывай `aria-keyshortcuts`; этот атрибут описывает сочетание, но обработчик всё равно нужен;
- после действия сохраняй или предсказуемо перемещай фокус и сообщай результат через видимое состояние или `aria-live`; глобальная клавиша смены выбранной строки меняет `aria-selected`, но не переносит фокус на строку, иначе пользователь видит одновременно маркер выбора и дополнительную рамку фокуса;
- не открывай модальное окно только ради списка клавиш. Сначала используй строку подсказок, `<details>` или небольшую панель справки.

Для физических клавиш навигации вроде `J` и `K` используй `event.code`, чтобы раскладка клавиатуры не меняла расположение команд. Для символа, который пользователь должен ввести, например `/` для поиска, проверяй `event.key`.

```html
<label class="search" for="queue-search">
  <span>Поиск</span>
  <input id="queue-search" type="search" aria-keyshortcuts="/">
  <kbd>/</kbd>
</label>

<p class="shortcut-hint">
  <kbd>J</kbd> следующий
  <kbd>K</kbd> предыдущий
</p>
```

```js
addEventListener("keydown", (event) => {
  const target = event.target instanceof Element ? event.target : null;
  const typing = target?.matches("input, textarea, select, [contenteditable]");

  if (event.key === "/" && !typing) {
    event.preventDefault();
    document.querySelector("#queue-search").focus();
    return;
  }

  if (typing || event.repeat) return;
  if (event.code === "KeyJ") selectNext();
  if (event.code === "KeyK") selectPrevious();
});
```

Не добавляй хоткеи по количеству доступных клавиш. Начни с двух или трёх команд, которые сокращают реальную повторяющуюся работу.

## Текстовый отчёт

```html
<section class="section">
  <article class="prose">
    <h2>Вывод</h2>
    <p>...</p>
    <pre><code>...</code></pre>
  </article>
</section>
```

`.prose` ограничивает длину строки, но не ширину всей рабочей поверхности.

## Финальное действие

```html
<aside class="callout">
  <strong>Следующий шаг</strong>
  <p>Решение, срок и ответственный.</p>
</aside>
```

Добавляй блок, только если у страницы есть следующее действие. Справочнику или исследовательскому инструменту он обычно не нужен.
