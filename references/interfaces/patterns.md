# Композиции интерфейсов

Интерфейсный стартер намеренно пуст. Выбери режим геометрии по содержанию, затем собери страницу из фрагментов `assets/interfaces/fragments/`. В [уровнях интерфейсной системы](atomic-design.md) эти режимы соответствуют шаблонам. Они задают раскладку, но не предметное содержание.

## Режимы геометрии

### Документ

Используй для последовательного чтения. Полноширинные секции получают `.document-band`, самостоятельные ограниченные блоки — `.document-block`, длинный текст — `.prose`. Навигацию добавляй из `section-nav.html`, когда заголовок документа уезжает при прокрутке.

### Поверхность данных

Используй всю ширину для таблиц, графиков и сравнений. Компактные параметры стоят рядом с заголовком или непосредственно над областью, которую меняют. Метрики поддерживают основной вывод и не образуют отдельную заставку.

### Рабочая поверхность

Основная интерактивная область начинается на первом экране. `split-workspace.html` даёт связанную пару основной области и деталей с независимой прокруткой на широком экране. На узком экране области идут последовательно и возвращаются к общей прокрутке страницы.

В связке «список и детали» выбор на узком экране должен быстро приводить к подробностям. После явного нажатия прокрути к началу панели деталей или открой её рядом с выбранной записью. Не делай этого при каждом нажатии стрелки: клавиатурный пользователь должен сохранить контекст списка. Если мобильная запись уже показывает поле, не повторяй его в соседней сводке.

Эти режимы не являются шаблонами страниц. Один материал может сочетать документные секции, полноширинные данные и отдельную рабочую область, если это следует из задачи.

## Доступные фрагменты

| Файл | Назначение |
|---|---|
| `page-head.html` | заголовок материала с кратким пояснением |
| `workspace-head.html` | компактный заголовок с управлением |
| `metric-strip.html` | короткая полоса показателей |
| `section.html` | самостоятельный раздел с пояснением |
| `split-workspace.html` | основная область и связанные детали |
| `data-table.html` | точная таблица в доступной области прокрутки |
| `empty-state.html` | отсутствие данных, результата или выбора |
| `section-nav.html` | навигация длинного документа |
| `field.html` | поле с подписью, подсказкой и ошибкой |
| `filter-bar.html` | параметры над изменяемой областью данных |
| `notice.html` | встроенное уведомление с меткой тона |
| `dialog.html` | нативное модальное окно с действиями |
| `kv-list.html` | список самостоятельных пар «поле — значение» |
| `timeline.html` | вертикальная хронология событий |
| `code-block.html` | код с источником и копированием |
| `tabs.html` | вкладки и связанные панели |
| `pagination.html` | постраничная навигация |
| `breadcrumbs.html` | положение материала в иерархии |
| `steps.html` | шаги процесса и текущее состояние |

Добавляй фрагмент через `scripts/compose.py`: сначала вызови `--list-placeholders`, затем передай текстовые значения через `--set`, а разметку через `--html` или `--html-file`. Не заменяй подстановки слепой строковой операцией. Если область не нужна, передай пустое значение только там, где пустой контейнер допустим по контракту; иначе выбери более простой фрагмент.

## Выбор представления

- Последовательный текст ограничивает длину строки, данные используют доступную ширину.
- Сравниваемые значения выравниваются по общей строке или колонке.
- Области равной важности разделяет линия, а не смена плоскости.
- Растущий поток получает всю строку вместо короткой соседней панели.
- Таблица с предложениями в ячейках на узком экране превращается в записи. Числовая таблица сохраняет колонки и допускает горизонтальную прокрутку.
- Пустое состояние объясняет, чего нет и какое действие доступно. Оно не рекламирует продукт.

## Локальные данные и JavaScript

Небольшой статический набор можно встроить в HTML или локальный скрипт. Большие данные при `file://` подключай обычным `<script>`, а не `fetch()` локального JSON. Состояние сохраняй в URL или `localStorage`, только если это помогает повторной работе.

Не подключай фреймворк ради статической страницы. JavaScript нужен взаимодействию, данным или механике формата, но не композиции.
