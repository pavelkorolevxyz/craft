# Паттерны страниц

Выбери ближайший паттерн, затем адаптируй композицию к данным. Не сохраняй секцию, если у неё нет полезного содержания.

## Дашборд состояния

Порядок:

1. Компактный `report-head`: название, главный вывод, период, актуальность.
2. `scoreboard` с 2–4 ключевыми показателями.
3. Главный график на 60–70% ширины и список сигналов рядом.
4. Точная таблица или журнал.
5. Действие только при наличии следующего шага.

Помещай фильтры в заголовок или непосредственно над данными, которые они изменяют. Не создавай отдельную глобальную шапку ради фильтров одного блока.

## Отчёт

Порядок:

1. Название, период, источник и вывод.
2. Краткая сводка: текст или 2–3 метрики.
3. Секции причины, последствия, детали.
4. Таблица или приложение с точными данными.
5. Решение, срок, ответственный.

Длинный текст помещай в `.prose`. Вся страница остаётся полноширинной, но длина строки текста ограничивается 65–75 символами.

## Демонстрационный инструмент

Порядок:

1. Рабочая панель управления с названием и состоянием.
2. Основная интерактивная область занимает большую часть области просмотра.
3. Параметры располагаются рядом с областью, которую меняют.
4. Результат и журнал разделены линией, а не карточной оболочкой.

Для инструмента допустима закреплённая боковая или верхняя панель, если навигация и элементы управления действительно используются. Высота основной рабочей области может быть `calc(100vh - <toolbar>)`. Не добавляй крупный промоблок.

## Сравнение

Порядок:

1. Вопрос или критерий сравнения.
2. Две асимметричные колонки либо строки по общим критериям.
3. Числовой итог.
4. Решение.

Используй общую сетку строк, чтобы значения читались по одной горизонтали. Не оформляй варианты независимыми маркетинговыми карточками.

## Каталог дизайн-системы

Пример находится в `assets/interfaces/specimen.html` и открывается через `file://`.

Структура:

1. Полезная навигация по разделам.
2. Короткое описание назначения.
3. Принципы.
4. Цветовые токены.
5. Типографическая шкала.
6. Пространственный ритм.
7. Элементы управления и состояния.
8. Представление данных.

Каталог показывает плотность и композицию, но не задаёт структуру каждого отчёта. Боковая панель нужна каталогу; одноразовому отчёту она обычно мешает.

## Локальные данные и JavaScript

- Встраивай небольшой статический набор данных прямо в HTML или `script.js`.
- Большой набор данных клади в `data/`. Браузер часто блокирует `fetch()` локального JSON при `file://`, поэтому для автономной работы подключай данные обычным `<script>` с присваиванием глобальной переменной. Локальный сервер может быть дополнительным режимом.
- Не используй фреймворк для статической страницы.
- Если взаимодействие требует состояния, храни его в URL или `localStorage`, когда это полезно пользователю.
- Показывай пустое состояние, ошибку разбора данных и отсутствие результатов.
