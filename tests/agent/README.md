# Проверка навыка независимыми агентами

Это проверка поведения модели на реальном материале, не замена тестам исходников. `task.md` содержит одинаковое задание на колоду и рабочую страницу. В нём намеренно есть независимые пункты, критерии с раскрытием, настоящий поток, равноправные способы проверки и фильтр с пустым результатом.

## Запуск

Из корня репозитория, с настроенным доступом к моделям:

```bash
python3 scripts/agent_eval.py --agent pi --model openai-codex/gpt-6-astra \
  --output artifacts/agent-eval/my-pi
python3 scripts/agent_eval.py --agent claude --model sonnet \
  --output artifacts/agent-eval/my-claude
```

Папка каждого прогона должна быть новой. Лимит по умолчанию 900 секунд, меняется через `--timeout`. Команды делают реальные обращения к моделям и не входят в `make test`. При необходимости запускай независимые прогоны параллельно, но не сравнивай их время как чистую скорость модели: нагрузка сервиса и машины различается.

Скрипт копирует навык в `craft/`, сохраняет `task.md`, `run.json`, `events.jsonl`, `stderr.log`. Агент получает только эту копию и пишет в `output/`. В `run.json` записаны версия CLI, модель, команда, хеш задания и документов, код завершения и время. Код 124 означает таймаут, не успешную сдачу.

У pi отключены сторонние расширения, навыки и файлы контекста; подключён только тестируемый Craft. У Claude отключены пользовательские настройки через `--safe-mode`, серверы MCP и интерактивное подтверждение. Разрешены чтение, запись, редактирование и Bash. Это раздельные рабочие папки и контекст, не ОС-песочница. Запускай только доверенное задание; модели имеют доступ через Bash к машине.

## Независимая проверка

Не меняй результат агента перед оценкой. Дождись поля `returncode` в `run.json`.

```bash
python3 scripts/check_project.py artifacts/agent-eval/my-pi/output/slides
python3 scripts/check_project.py artifacts/agent-eval/my-pi/output/interface
node tests/agent/browser.mjs artifacts/agent-eval/my-pi
```

Нужны Node.js с встроенным WebSocket и Chromium. `CHROMIUM` задаёт путь браузера. Браузерный сценарий сохраняет в `review/` отдельный снимок каждого экранного состояния колоды, страницу в обеих темах на 1440, 390 и 320 px, поиск, пустой результат, выбор, PDF и `browser.json`.

Навигация колоды, Tab, Enter, стрелки и выбор записи мышью проходят через CDP Input. Enter включает событие `char`, необходимое для нативной активации кнопки. Перед кликом запись прокручивается без плавного движения. Счётчики слайдов успевают дойти до конечного значения перед снимком. Поиск и фильтр меняются через DOM с соответствующим событием, сброс вызывается через `.click()`. Нативное меню фильтра этим не проверяется. Сценарий распознаёт варианты таблицы и списка из задания, не является универсальным тестом любого интерфейса. При другой структуре сначала проверь селектор теста, не объявляй ошибку приложения по отсутствию знакомого класса.

Проверь глазами снимки и PDF. По `browser.json` сверь:

- независимые направления остались списком, не сравнением;
- критерии появляются в четырёх кадрах: заголовок, один, два и три критерия;
- поток появляется как клиент, затем связь с сервером, затем связь с журналом; нет постоянного акцентного узла;
- варианты не названы "Было / Стало", сохранены 40 и 8 минут и одинаковые 12 сценариев;
- поиск выдаёт одну запись, сочетание с "Готово" даёт ноль, сброс возвращает четыре;
- пустой набор не оставляет старые подробности, выбор мышью и клавиатурой обновляет их;
- печатается текущий набор, не исходные или невидимые выбранные данные.

`checks.md` агента не считается доказательством без файлов и воспроизводимых команд. Записывай отдельно семантику, механику, внешний вид и завершённость прогона. Один успешный пример не доказывает надёжность навыка, один таймаут не доказывает плохое качество разметки.
